# Phone performance, 2026-09-21

The host baseline is `.scratch/speed-baseline.md`; Hook measurements and
regression rules are in [docs/performance.md](../../../docs/performance.md).
All Swift measurements below use a local Apple silicon macOS debug build.
They are not iPhone release-build or frame-rate measurements.

## Measured changes

| Measurement | Before | After |
|---|---:|---:|
| Heavy transcript decode, debug median | 122.32 ms | 29.71 ms |
| Workspace envelope and decode, paired mean | 2.06 ms | 1.58 ms |
| iOS graph bundle | 1,999,839 bytes | 1,409,042 bytes |
| Graph V8 compile proxy, median | 42.44 ms | 21.56 ms |

Workspace validation and decoding of a 240-tab, 47,176-byte response took
2.06 ms before and 1.58 ms after, averaged over 30 paired iterations in the
same test process. `PhrenConnection.fetch` previously parsed the entire
response with JSONSerialization to inspect two envelope fields, then parsed
it again with Codable. `LiveWorkspaces.read(..., requiringHook: true)` now
validates those fields during the existing decode. Older internal fixtures
can still use the non-gateway reader. Tests cover missing, wrong and supported
product/protocol values and encoded round trips.

Transcript text arrives from Foundation JSON with NSString-backed storage.
`AgentChatTranscript.boundedMessageText` materializes contiguous UTF-8 once
before applying the existing 64,000-grapheme limit. A byte count is used only
as an upper bound to bypass truncation when it is provably unnecessary.
Combining accents and multi-scalar emoji tests compare the result with the
original Character-prefix behavior. This does not change message IDs,
render keys, text limits or truncation semantics. Ten-iteration paired full-page decode runs measured a median of 122.32 ms
before and 29.71 ms after (75.7% lower). The fixture is 1,507,206 bytes with
60 transport entries and 80 prepared message parts.

The iOS graph is 1,409,042 bytes, down from 1,999,839 bytes. Its optional
WebGPU dependency is excluded because this app uses WebGL. The actual app
bundler is checked against a 1,500,000-byte ceiling. First-paint work still
includes label renderer creation, WebGL initialization, bloom and halo
resources, deterministic layout/cages and navigation. Labels and bloom were
not deferred without a browser lifecycle test. Local V8 compilation improved
from 42.44 to 21.56 ms; actual WKWebView paint remains unmeasured.

## Fixtures and guards

`PhrenKit/Tests/PhrenKitTests/PhonePerformanceTests.swift` measures the
1,507,206-byte, 60-entry heavy transcript, the 240-tab overview, a 15,559-byte
usage response with five accounts and 150 windows, and the checked-in
`hook-events.json` contract (3,407 bytes). There are no larger checked-in
overview or usage JSON fixtures; those two stress payloads are generated by
the test. The heavy generator reproduces the app's heavy fixture. Keep it in
step when that fixture changes.

The checked-in transcript contract takes about 0.12 ms to decode and the
synthetic usage response about 0.45 ms. Neither decoder was changed.
`ChatTranscriptPerformanceTests` now measures actual app-level preparation
plus 60 unchanged updates, in addition to its existing revision-reuse test.
It cannot run without the app test host. PhrenKit separately measures message
text preparation and the full heavy decode. Do not confuse those operations
with SwiftUI layout, Markdown rendering or the app's full preparation pass.

## Paths inspected and left alone

The SSH pool already deduplicates authentication, shares a connection per
host/key/fingerprint, limits pooled child channels to eight, and retains idle
connections for 90 seconds. A warm request still needs a channel-open exchange
and an exec acknowledgement before HTTP. NIO already decodes fragmented
HTTP/WebSocket frames incrementally. No live host was used, so channel-open
milliseconds and cold authentication cost are unknown. Keep
`PHREN_PERFORMANCE_LOG=1` marks for dial, authentication, pool reuse and request
completion when profiling a real phone.

The installed gateway chooses socat, then nc with Unix socket support, then
Node as its fallback. Thus a supported native forwarder already avoids a new
Node process for each byte pipe. The Node path records process-start through
first response byte in `gateway.json`. Changing SSH pooling, authentication
or stream framing without runnable socket tests was judged too risky.

`AppModel.init` assigns dependencies and empty state. Credentials already
load in a detached task. Before the first scene task, `PhrenApp` constructs
appearance/approval singletons and applies UIKit chrome; preferences still
use UserDefaults. Store bootstrap, ActivityKit reconciliation, saved-host
registration and navigation restoration run in the scene task. The existing
first-scene-task timing mark does not establish first displayed frame. No
launch change was justified without a device or simulator trace.

Widgets decode a snapshot when WidgetKit requests a timeline, with a
15-minute fallback refresh, rather than on a display tick. Working-activity
updates consume typed session data and throttle publication; JSON route
restoration occurs when opening a saved route. No extra caching was added.
The reserved chat, overview and native-control sources were not edited.

## Validation and limits

The iOS project was generated successfully. Build-for-testing failed before
app compilation: default manifest caches were outside the writable sandbox;
a retry with local caches and copied dependency checkouts reported missing
PhrenKit, PhrenLive and SwiftTerm package products. CoreSimulator was also
unavailable. Consequently app preparation timing, launch-to-first-frame and
WKWebView first-paint numbers are still outstanding.

PhrenLive compiled using existing dependency checkouts copied into `.scratch`.
Its full test run cannot bind loopback sockets in this environment. The
non-socket subset passed 47 tests, including incremental framing and request
validation. No dependency lockfile changes are part of this optimization.
PhrenKit passed all 523 tests, including the performance measures and Unicode
truncation guards.
